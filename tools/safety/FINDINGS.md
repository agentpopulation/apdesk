# Safety probes: findings and status

Each script in `tools/safety/` attacks one door with a throwaway `testDesk` (fake model, no keys) and prints `HELD` or
`BYPASS` with one line of evidence. Run one from the repository root: `node tools/safety/02_module_db_sql.js`.

**Status (all scripts run 14 Nov 2026, IST):** every probe prints `HELD` except `05_panic.js` `BYPASS(timer)`, the
accepted limit described under "Carried over / accepted" below. The findings tables are kept as the record of what each
probe was written to catch; every finding in them is closed except that one.

`21_people.js` (21 Nov 2026, IST): several people on one PC. A non-keeper installing an update, switching a module or
going Offline; one person's token reading the other's chats, keys and events; 40 PIN guesses at once (no wrong PIN gets a
token, the right one still enters); a rival flooding wrong PINs to lock the keeper out (the keeper's own PIN still
enters); a non-keeper asking for the house pairing code; a non-keeper switching paid OpenRouter on (the PC's shared key);
a non-keeper reading the keeper's backups outside the data folder through Files; the looks route with security, spend and
other keys. All `HELD`; the keeper's own token is the control. Fixes (21 Nov 2026): `people.js · check()` honours the
right PIN during a wait; `server.js · KEEPER_ONLY` adds `pair-code` and `paid-models`; `settings-routes.js · spend`
no longer flips paid; `explorer.js · isBlocked` shields the keeper's backups (`env.houseBackups`).

The probes were written in two passes on 13 Nov 2026. The second pass (modules, and a re-check of the first-pass fixes)
comes first; the first pass is kept below it.

## What HELD in the second pass (script)

- **First-pass #1 (self-approve)**: `ctx.approval.decide` is gone; a module's `request()` stays pending. `01`.
- **First-pass #2 direct SQL**: plain / quoted / `main.`-qualified / CTE / single-statement comma-join / single-statement trigger / temp-table shadow of a core name / `ATTACH` / `VACUUM` / `PRAGMA writable_schema` are all refused. (Multi-statement and DDL are R2-1.) `02`.
- **First-pass #3/#4 (binding, folders)**: recipient swap, extra field, and `..`/Windows-case folder climbs are refused; binding is single-use and does **not** survive a restart. `03`.
- **First-pass #5 (session rule)**: all 161 module write routes and the core write routes refuse without the session (403); `//api`, `/api//`, `/api/.`/`%2e`, case spellings change nothing. `04`.
- **Spend amounts**: negative / `NaN` / `'abc'` / `0` / missing all ask. `03`.
- **`/router/v1`** never falls through to a paid key; **no key value** appears in `/api/state`, `/api/settings`, `/api/model/usage`, `/api/keys/services`, `/api/activity`, `/api/approvals` or 72 module GET routes. `04`.
- **Panic**: resume needs the session and refuses a cross-site Origin; a streaming reply is cut; a **code-run child process and an MCP server child process are both gone 2 s after Panic**, jobs are `stopped`, and a new tool call is refused `halted`. `05`, `14`.
- **`ctx.fetch`** cannot reach the desk by any loopback spelling; **settings body tricks** (`__proto__`, spaces, case, `ui.*`) change nothing; **reserved events** cannot be forged on the shell's channel. `06`, `07`, `15`.
- **Send paths** (mail, channels, social) each call `assertGranted(id,'send.person', <exact item>)` right before the send; the Telegram reply path refuses any chat not on the allow-list. Read in `modules/{mail,channels,social}/server.js`.
- **Vault/Accounts**: reveal/login/key routes are owner-gated; `loginFor` needs a granted `login` approval; the lock returns 423 for everything but state/events/Panic/unlock (`app/server.js`), PIN compared with `timingSafeEqual`. Read in `modules/{vault,accounts}/server.js`.

## Carried over / accepted (stated, not padded)

- Token on the index page (first-pass #6): closed later by browser pairing (`08_token_from_index.js` prints HELD).

# First pass: Agent Population Desk core (approval door, Panic, model door, network face)

Everything below was run against a throwaway `testDesk` (fake model) with the scripts in
`tools/safety/`. Each script prints `BYPASS` or `HELD` with one line of evidence. Probe module:
`tools/safety/evil-modules/evil/` (+ `fetcher/`) — uses only the published `ctx` surface a real module gets.

Severity = what the actor can do **on its own**: critical = an agent/module/web page can send, spend, approve,
change the security level, or resume after Panic without the owner. Loopback-only, single-owner scope is applied
when judging reach.

## What HELD (with the script that shows it)

- **Level / auto-approve / spend cannot be set without the session**, via any route or body trick — prototype-pollution
  keys (`__proto__`,`constructor`), trailing/leading space, case and `ui.*` variants of `security.level`, and the plain
  `POST /api/settings` route (allow-list, not deny-list). `07_settings_body_tricks.js`, `04_network_model_secrets.js`.
- **Modules get no setter**: `ctx.approval.setLevel` and `ctx.settings.set` are `undefined`; `setLevel` throws without the
  real `SETTINGS_TOKEN` symbol. `01_module_self_approve.js` (caps line), existing `core.test.js`.
- **Cross-site writes refused** (Origin + `Sec-Fetch-Site`) and **foreign Host refused** (DNS rebinding); GET cannot reach a
  state-changing route (method-specific matching). `04_network_model_secrets.js`, existing `core.test.js`.
- **Resume is gated**: `POST /api/panic/resume` needs the session and refuses a cross-site Origin; `POST /api/panic` is
  intentionally unauthenticated (easy to stop, hard to resume). `05_panic.js`.
- **Panic cuts a live streaming reply** and halts new work until Resume. `05_panic.js`, existing `core.test.js`.
- **`/router/v1` is limited to the free router** — it forces `{provider:'router'}` and never consults paid keyed secrets,
  so another local program cannot burn paid keys through it (unlike #5's `/api/model/ask`). `04_network_model_secrets.js`.
- **No secret values leak** from `/api/state` or `/api/settings` (`router.apiKey` and provider keys absent); approval
  payloads are redacted by `redact()`; model keys come back masked. `04_network_model_secrets.js`.
- **`ctx.fetch` cannot reach the desk** via alternate loopback spellings — the WHATWG URL parser normalizes `127.1` /
  decimal `2130706433` to `127.0.0.1` (caught by the guard), and the server Host allow-list refuses every other spelling
  (`[::ffff:127.0.0.1]`, hostnames). `06_ctx_fetch_loopback.js`.
- **Static serving**: `/ui/..%2Fserver.js` and off/other-module `/modules/...` are 404. Existing `core.test.js`.
- **`assertGranted` is single-use** (a grant can't be replayed for a second send). `03_approval_door_tricks.js`.
- **No skip parameter and no chat phrase**: no `skipGate`-style skip parameter on any action, and the door ignores message
  text (no chat phrase opens auto-approve). Confirmed by reading `approval-door.js`; the only auto-approve path is the
  session-gated `setAutoApprove`.

## Deliberately not flagged (loopback-only, single-owner makes them irrelevant)

- `POST /api/panic` being unauthenticated is correct, not a hole; an agent spamming Panic is a nuisance the owner clears
  with one gated Resume.
- Several "a local process could ..." escalations (token scrape #6, reading keys) reduce to: a hostile non-APD process on
  this PC already has the data folder. Listed where they add a *live-action* capability (#6), not padded elsewhere.

## Not checked
- Anything requiring a **real** provider key or a real browser: whether a keyed `send`/payment actually leaves the
  PC, and the browser module's handling of #6 (an agent browser executing same-origin script on `/`). The browser,
  mail, payments and vault modules were added after this pass; the second pass covers them.
